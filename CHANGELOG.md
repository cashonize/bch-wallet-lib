# Changelog

## Unreleased

Starting point: mainnet-js `4.0.0-next.14` (`next` @ `9ec2a0e`), plus mainnet-js#244 (128-byte NFT commitments).

### Changes for callers coming from mainnet-js

- Package name `bch-wallet-lib`; `@mainnet-cash/indexeddb-storage` is now the `bch-wallet-lib/indexeddb` subpath export.
- The CLI (`src/cli.ts`) and the browser bundle are not shipped.
- The Electrum transport is `@electrum-cash/network` with `@electrum-cash/web-socket` instead of `@rpckit/*`:
  - Servers are plain URLs, `wss://host:port` or `ws://host:port`. `createProvider(network, servers?, options?)` and `DefaultProvider.servers.<network>` take one URL, several separated by commas, or an array (`getDefaultServers` now returns an array). A list is tried in order when connecting, and the provider stays with the first server that connects: after a failure electrum-cash reconnects to that server and restores its subscriptions there. rpckit's notation (`fallback(...)`, `?timeout=…&batchSize=…` options) is rejected with an Error, and requests are no longer batched.
  - `new ElectrumNetworkProvider(transport, network)` takes a `Transport`, the new interface of what the provider needs (`connect`, `close`, `request`, `subscribe`), e.g. `new ElectrumTransport("wss://host:50004")`. The class is no longer generic over an rpckit schema, and `performRequest<T>(method, params)` / `subscribeRequest(method, params, callback)` take the result type from the caller instead of the schema.
  - Every server gets a connect timeout (10 s) and a request timeout (30 s), a single user-supplied URL included (mainnet-js#251); `ElectrumTransportOptions` (`connectTimeout`, `requestTimeout`, in ms) is the third argument of `createProvider`. A timed out request rejects with an `ElectrumTimeoutError`, no longer with the string `"electrum-cash request timed out, retrying"`. A request that times out or loses its connection is sent once more, now really re-sent on a (re)connected server rather than awaited again; a broadcast is not, and an error response from the server is never retried. Errors are always `Error` objects.
  - In a browser the socket stays connected while the page is hidden and ignores online/offline events; it reconnects when the connection actually fails. In Node, TLS certificates are verified.
  - Protocol version 1.5 is asked of every server (mainnet asked for 1.6), as electrum-cash only accepts the exact version it asks for and chipnet servers stop at 1.5.
  - `daemonPassthrough()` is removed: Fulcrum's `daemon.passthrough` takes named params, which electrum-cash cannot send. The regtest `mine()` calls the node's RPC directly, with the `RPC_*` environment of the regtest (as mainnet-js 3 did).
  - New exports: `ElectrumTransport`, `ElectrumTimeoutError`, and the types `ElectrumServer`, `ElectrumTransportOptions`, `Transport`, `Unsubscribe`.
- `initProviders` / `disconnectProviders` no longer throw a `ReferenceError` in a browser that has no global `process` (mainnet-js#251).
- `createMockProvider` and `MockNetworkProvider` are now exported from the new `bch-wallet-lib/mock` subpath, which needs `@paryonusd/mem-cash` installed; the main entry no longer imports them, not even dynamically, so bundlers no longer fail on the mock chain's imports (mainnet-js#251). `initProvider` / `initProviders` / `disconnectProviders` no longer read `USE_MOCK_PROVIDER`: call `initMockProvider()` from `bch-wallet-lib/mock` to install a mock chain as the regtest provider.
- The HD wallet cache drops entries left in the pre-next.14 format (keyed `${walletId}-${index}-${change}`, with an `indexCache`) when it loads, and rewrites the stored record without them; they held private keys and were carried forward on every write without being read (mainnet-js#251).
- `GAP_SIZE`, `DEFAULT_BRANCHES`, `DEPOSIT_BRANCH`, `CHANGE_BRANCH` and the `HDWalletOptions` type are exported from the entry again, as in mainnet-js 3 (mainnet-js#251).
- `sendMax`, `send` and the token operations no longer write to the caller's options object (`sendMax` set `options.utxoIds`, a token send appended to `options.ensureUtxos`), nor does `waitForTransaction` (`getTransactionInfo`), so reusing an options object, e.g. for a retry, no longer carries the previous inputs forward (mainnet-js#251).
- New export `InsufficientFundsError`, thrown wherever the wallet's coins (or the given `utxoIds`) cannot cover a send, a genesis, a mint or a burn, with `asset` (`"bch"` or `"token"`) and, for a token, its `category`; tell it apart with `instanceof` instead of matching messages. The messages are unchanged: "Amount required was not met…", "There were no Unspent Outputs", "The available inputs couldn't satisfy the request with fees", "The available inputs in the wallet cannot satisfy this send request", "Insufficient funds for transaction given fee", "Not enough vout=0 inputs available for new token genesis…", "Not enough token amount to send", "No suitable token utxos available to send token…", "You do not have any token UTXOs with minting capability…", "You do not have suitable token UTXOs to perform burn…" (mainnet-js#251).
- New `wallet.setProvider(provider)` switches an existing wallet to another electrum provider of its network: the wallet's subscriptions (status watches, an HD wallet's address discovery, `watchBlocks`, and pending `waitForTransaction` / `watchDoubleSpends` subscriptions) are made again on the new provider and ended on the old one, which is left connected (mainnet-js#251). If the new provider cannot connect, or a subscription cannot be made there, `setProvider` rejects and the wallet stays on the old provider with its subscriptions; a retry with the same provider tries again. Moved status watches get the new server's current status, as when they start; a moved `watchBlocks` callback gets the new server's tip only if it differs from the last header it saw. `wallet.provider` is now a getter: assigning it (the old workaround, under a `@ts-ignore`) throws a `TypeError`, so call `await wallet.setProvider(provider)` instead. `waitForBlock` still waits on the provider it started on.
- `wallet.stop()` now also ends `watchBlocks` subscriptions and pending `waitForTransaction({ txHash })` / `watchDoubleSpends` subscriptions, which it left running before. The protected `cancelFns` / `trackCancelFn` are replaced by the protected `subscribe(fn)`.
- `waitForTransaction({ txHash })` for a transaction the server already knows now ends its subscription; it left it running, and with `setProvider` it would have followed the wallet to each new provider.
- A subscription that cannot be made (e.g. the server is unreachable) no longer leaves what waits on it pending forever (part of mainnet-js#256): `waitForTransaction`, `waitForBalance`, `waitForTokenBalance`, `waitForBlock` and `sendRawTransaction(hex, true)` reject with the error. When a wallet's own status subscription fails as it is constructed (a single-address wallet's address, or an address of HD discovery), `getUtxos`, `getBalance`, `getRawHistory` and `watchStatus` no longer hang but go on with the cached state; `scanMoreAddresses` rejects with the error, and later reads go on with what was discovered. A failure in the first fetch after a status notification still leaves HD discovery pending, as before.
- A watch-only or single-address wallet's `waitForUpdate` starts its timeout once its status watch is in place, as the HD wallet's does; it threw a `TypeError` when the wallet's first subscription took longer than the timeout.
- A wallet cache write that fails (e.g. storage full) and an exchange rate that cannot be cached no longer surface as unhandled promise rejections, which end a Node process by default; the cache write is redone by the next one, and the rate is still returned.
