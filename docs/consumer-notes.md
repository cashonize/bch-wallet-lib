# What a real consumer needs: notes from Cashonize

Cashonize (`~/Cashonize/cashonize-wallet`) is this library's first user. It runs on mainnet-js 3.x with a pnpm patch. In many places it reimplements a mainnet-js helper, calls smaller pieces instead of a larger helper, or works around library behavior. This file lists those places, why Cashonize does it, and what that means for the library's API. Cashonize sites are named by file and function; line numbers drift.

The inventory this builds on, written for the fork decision, is `~/Cashonize/mainnet-js-fork/research/cashonize-usage.md` (sections 4 and 7: where the app bypasses mainnet-js and the workarounds it carries). This file adds the reasons and the API conclusions.

Section 3 lists what is still open, section 4 what is fixed, section 6 what was removed that a consumer may want back. `docs/api-surface.md` lists every export with the Cashonize site that uses it. Commit hashes of this library refer to the development history kept on the `archive/dev-history` branch; Cashonize hashes are of the migration branch.

## 1. The pattern: the caller owns the async steps

The reimplementations share a few causes. They make good API rules:

1. **One snapshot, many views.** The app reads the utxo set once and computes everything from it: the balance, token lists, the spendable pool after reservations, address rows. The wallet method `getBalance` calls `getUtxos()` again. Cashonize therefore wrote its own pure versions (`utils.ts` `getBalanceFromUtxos`, `getFungibleTokenBalances`, `getAllNftTokenBalances`; `storeUtils.ts` `tokenListFromUtxos`). **Rule:** every derived value is a pure function over a `Utxo[]`.
2. **The caller sets the concurrency.** The app paces its own requests:
   - authchain walks run at most 10 at once, with spender searches in batches of 50 that stop early (`electrumAuthchain.ts`);
   - Cauldron pool lookups go in batches of 10, and a failed lookup is skipped (`cauldronPools.ts`);
   - the derivation-path scan runs in batches of 10 and stops early (`walletUtils.ts` `scanDerivationPaths`).

   The library does the opposite. `getRawTransactions` and `getHeaders` send every cache miss in one unbounded `Promise.all`, and one failure rejects the whole batch. History backfills balances with one `getBalance` request per address. **Rule:** the library offers single-step primitives, and where it fans out itself, the fan-out is capped and fails per item.

3. **Every step can be checked, cancelled or shown.** The app interleaves its own steps:
   - `transferAssets.ts` re-reads the pool before each of its 2N+1 sends and reports progress between them;
   - the sweep previews the coins before anything is broadcast;
   - history loads 100 entries first and the rest when idle, with a stale-request id and one shared in-flight load (`store.ts` `updateWalletHistory`, `loadFullHistory`);
   - connecting uses a 3 s and then a 12 s window (`utils.ts` `connectElectrum`).

   **Rule:** build without broadcasting (`broadcast: false` plus `submitTransaction` already does this), keep paging, and leave timeouts configurable.

4. **Explicit choices instead of implicit order.** Cashonize relies on things the library happens to do:
   - `tokenGenesis` spends the first vout-0 coin of the pool, so the app puts its chosen coin first;
   - requested outputs come first, so it assumes the new coin is `${txId}:0` (`genesisInputPicker.vue`, `flipstarterPledge.vue`, `store.ts` `spendAuthUtxo`);
   - `tokenMint` takes the first minting NFT of the category.

   **Rule:** let the caller name the coin, and report outpoints in the result.

5. **No side effects from looking.** Some calls that only look still construct things:
   - mainnet-js's `namedExists` constructed a wallet, which pinned the global provider (round 3 replaced it with the free `namedWalletExists`, which constructs none);
   - a wallet is constructed on the global provider before the app can choose a server;
   - the derivation scan builds about 83 wallets, and on v4 each one subscribes as it is constructed.

   Cashonize works around these with raw IndexedDB (`dbUtils.ts` `namedWalletExistsInDb`), `DefaultProvider.servers` set before the first wallet is constructed, and `Config.DefaultParentDerivationPath` set before `named()`. **Rule:** reads and existence checks construct nothing and subscribe to nothing, and per-call options replace global config.

6. **Errors the app can tell apart.** Cashonize matches error strings to localize messages and to explain reservations (`store.ts` `shortfallMessages`, `broadcastErrors.ts` `classifyBroadcastError`). It also has `typeof error === 'string'` branches, because mainnet-js throws strings. **Rule:** typed `Error` subclasses with fields such as `asset`, `category` and `reason`, and never a thrown string.

7. **State the app can observe, storage it doesn't have to mirror.** The wallet mutates its own internals, so Cashonize keeps it in a `shallowRef` and uses its own `walletUtxos` as the change signal (`store.ts` `walletHasAddress` next to `wallet.hasAddress`). It also opens the library's IndexedDB databases itself and has to match their names, versions and key formats (`cacheUtils.ts`, `dbUtils.ts`); a mistake there fails silently. **Rule:** changes reach the app through watch callbacks or returned snapshots, and every storage operation an app needs (list, delete, prune, clear caches) is library API.

## 3. Open library work, by priority

Done in round 2 and moved to section 4: reserved coins out of every spend (`excludeUtxoIds`, `ensureUtxos` inside the pool), the exchange-rate fallback, request validation, cheaper history. Done in round 3 and moved to section 4: the provider chosen at construction, saving and existence checks that construct nothing, an address scan that constructs no wallets (app side), typed errors for a missing `utxoIds` coin, walletIds, WIFs and the IndexedDB cache, storage helpers that skip a bad row, and burns of exactly what is asked. The relay-fee setting errors stay plain `Error`s: they are programmer errors.

1. **Explicit coins in token operations.**
   - A `genesisInputs` option on `tokenGenesis` that throws if the coin isn't available (today: narrow with `utxoIds` and rely on order).
   - The minting utxo and its return address as options on `tokenMint`.
   - The outpoint of each requested output in `SendResponse`.
2. **Public HD address info.** Add `addressInfo(branch, index)` returning `{address, tokenAddress, publicKeyHash, used, txCount, utxos}`, and make `getUsedAddresses(branch)` public. Also derive addresses on untracked branches, such as the defi chain 7, without counting them in the balance. Cashonize reads `walletCache` and the raw history maps directly (`addressRows.ts`, `hdAddresses.vue`, `hdAddressSelect.vue`, `wizSigning.ts`, `cauldronPools.ts`).
3. **History.** Let `getRawTransactions` and `getHeaders` fail per item; one failure still rejects the whole call. An HD wallet's address discovery still subscribes, and fetches for, every address of a gap extension at once.
4. **Smaller additions.**
   - Export `utxoToSourceOutput(utxo)`, which the library's own `prepareInputs` and `prepareTokenOutputs` also use. Cashonize has three copies (`utxoConverter.ts`, `flipstarter.ts`, `cashconnectStore.ts`), and `prepareInputs` quietly uses a zero key when the cache has none.
   - Add `provider.getSourceOutput(txid, vout)` with exact bigints.
   - Add a wallet-level `signMessage(message, address?)`.
   - Accept the token form of an address in `hasAddress`, or add `hasLockingBytecode`.
   - Add a derivation option on `named` / `newRandom`.
   - Add `skipInitial` on `watchBalance`, as `watchBlocks` already has (`watchStatus` is internal now).
   - Check the 100 kB standard size before signing.
5. **The genesis input pre-read.** The input of `tokenGenesis` is the first vout-0 coin in `utxoIds` order, so Cashonize reads the pool to put its chosen coin first (item 1). The identity spends' token-coin pre-read is gone: `tokenUtxoIds` (section 4).
6. **Open questions from the round 3 review.**
   - `asSendRequestObject` still accepts the REST forms `{ dataString }` and `{ dataBuffer }` (base64) as OP_RETURN requests: keep them typed, or drop them now that the tuple forms are gone.
   - `getXPubKey(seed, "m", network)` derives the root key without complaint, where `deriveHdPaths` refused it.
   - `checkProviderNetwork` (a provider of another network) and the exchange-rate fetch errors are plain `Error`s; a caller branching on them would want typed ones.
   - `InsufficientFundsError.data` (`required`, `available`) is set on the error but not declared on the class.
   - A new mutable NFT request falls back on spending the minting NFT (the baton) when no mutable NFT is left to claim: decide whether that should need an explicit opt-in.
   - Several `tokenBurn` requests of one category are not merged: each spends its own coins. Merging them per category would spend fewer coins; decide whether a caller should merge them itself.
   - `MockNetworkProvider.connect` sets the mock chain up but skips `ElectrumNetworkProvider.connect`, and with it `cache.init`, so tests on the mock chain never open the IndexedDB cache through the provider.
   - Further removal candidates with no Cashonize use (see `docs/api-surface.md`): `newRandom`, `getRawHistory`, `getAddressByBranch` / `getTokenAddressByBranch`, `getTransactionHash`, `subscribeToTransaction`, `provider.connect()`, and `replaceNamed` once Cashonize stores with `saveNamedWallet`.

## 5. API breaks Cashonize will hit

- `wallet.provider = …` throws, because `provider` is now a getter; use `setProvider`. `Connection` no longer exists; use `createProvider`.
- `wallet.sign()` and `wallet.verify()` no longer exist; use `SignedMessage.sign` / `verify`. `verify` takes the address as a required argument, and the responses carry only `signature` and `valid`. Cashonize already calls the static forms.
- `Network` is no longer exported: `Network.MAINNET` becomes `NetworkType.Mainnet` (`walletUtils.ts` and its mock).
- `tokenMint(mintRequests, options)`: the category now goes inside each request, and the `deductTokenAmount` parameter is gone. `getMaxAmountToSend(options)` takes the options directly, without the `{ options }` wrapper.
- The HD fields `depositIndex`, `changeIndex`, `depositRawHistory` and `changeRawHistory` are replaced by per-branch `indices` / `rawHistory` maps. `walletCache.getByIndex(i, change)` became `getByIndex(i, branch)`.
- Single-address wallets now subscribe on construction (their cache stays in memory, as in 3.1.7). Never construct one just to look something up.
- `wallet.walletType` is protected (round 3). `WalletPage.vue` tells an HD wallet by it; use `instanceof HDWallet` or `settingsStore.getWalletType` instead.
- `watchBalance` still fires once on subscribe, so Cashonize's `electrumSubscriptionsActive` guard stays.
- A `TokenSendRequest` with amount 0 and no NFT now throws `InvalidRequestError`. `createTokens.vue` builds one when the circulating amount is 0; skip that output instead.
- Coins picked for mutable-NFT requests now come after those of the other NFT requests in the inputs, before the fungible token coins; `ensureUtxos` still go first.
- A `tokenBurn` of more fungible tokens than the matching coins carry now throws `InsufficientFundsError` (`asset: "token"`), where it burned them all. `tokenItemFT.vue` checks the amount against the spendable balance first; if that balance counts fungible tokens on NFT coins, which a burn without an NFT does not spend, the error reaches the user.
- A `tokenBurn` request with amount 0 and no NFT now throws `InvalidRequestError`. `tokenItemFT.vue` only checks that the typed amount is not empty, so `0` reaches the library; check for a positive amount there.
- mainnet-js 3.1.7 can't open an `hd:<xprv>` row, so a wallet stored that way can't be rolled back. Cashonize stores its HD wallets by mnemonic only (`walletUtils.ts`, `hd:<network>:<mnemonic>:<path>:0:0`), so a rollback keeps them; keep it that way while a rollback to 3.1.7 is possible.
- `ExchangeRate.get(currency, true)` is gone: `store.ts` reads `(await ExchangeRate.getQuote(currency)).rate`, or passes `{ staleOnError: true }` and replaces `currentExchangeRate`'s fallback (section 4).
- The `NetworkProvider` type is gone: `test/bchWalletLib.test.ts` casts its mock provider to `ElectrumNetworkProvider` instead (lines 15 and 40).
- The free `getHistory` requires `utxos`; the test that calls it already passes `utxos: []`. Its `unit`, `start`, `fromHeight` and `toHeight` options are gone, which Cashonize never passed.
- A `sendMax` whose max is below the destination's dust limit throws `InsufficientFundsError` (`asset: "bch"`) before anything is built, where the broadcast was refused as `"dust"` with `BroadcastRejectedError`. The single-coin send in `utxoManagement.vue` hits it for a coin too small to send; `store.ts` `spendExplained` explains it only when coins are reserved.
- `named`, `replaceNamed` and `newRandom` lose their `dbName` parameter, and `named` its `force`; Cashonize passes neither. The watches take no options (`onError` is gone); Cashonize passes none.
- `getNamedWalletId` returns `undefined` for a row holding an empty id, which `store.ts` `loadExistingWallet` already treats as missing.
- The category of a token request, and the NFT commitment of a send or burn request, are lowercased by the constructor; `SendResponse.categories` lists them lowercased. Cashonize passes the categories of its utxos, which electrum gives in lowercase, so nothing changes there.
- Removed in round 3 that Cashonize used, each handled above or on the branch: `Network` (`walletUtils.ts`), the `NetworkProvider` type (tests), `ExchangeRate.get`, `walletType` (now protected), `deductTokenAmount`, the `{ options }` wrapper of `getMaxAmountToSend`, `Wallet.fromSeed` (the import scan, gone on the branch in `e747c92`).
- Removed in round 3 that Cashonize never used, so nothing changes there (CHANGELOG.md "Removed" has the replacements):
  - Entries: `bch-wallet-lib/encrypted-storage`, `bch-wallet-lib/coin-control`, `bch-wallet-lib/mock`.

  - Helpers: the `libauth` namespace, `binToHex`, `hexToBin`, `atob`, `btoa`, `getWeakRandomInt`, `sanitizeAddress`, `derivedNetwork`, `isValidAddress`, `deriveTokenaddr`, `convertAddress`, `toBch`, `toSat`, `toCurrency`, `convertObject`, `getAddrsByXpubKeyObject`, `getXpubKeyInfo`, `getXpubKeyInfoObject`, `deriveHdPaths`, `getXPubKeys`, `XPubKey`, `DERIVATION_PATHS`, `decodeTransaction`, and the entry's internal helpers (`amountInSatoshi`, `sanitizeUnit`, `UnitEnum`, `checkUtxos`, `delay`, `deriveCashaddr`, `toCashaddr`, `toTokenaddr`, `isTokenaddr`, `checkTokenaddr`, `derivePublicKeyHash`, `derivePublicNodeCashaddr`, `getRuntimePlatform`, `RuntimePlatform`, `hash160`, `sumUtxoValue`, `sumTokenAmounts`, `UtxoId`, `PrivateKeyI`).

  - Wallets: `wallet.sign` and `verify` (Cashonize calls the static forms), `BaseWallet.namedExists` (`dbUtils.ts` reads IndexedDB itself), `createWallet` and the rest of `wallet/createWallet.ts`, `getInfo`, `toString`, `getSeed`, `isTestnet`, `WalletRequestI`, `WalletResponseI`, `WalletInfoI`, `MnemonicI`, `WalletI`, `waitForBalance`, `watchTokenBalance`, `waitForTokenBalance`, `getLastTransaction`, `waitForTransaction`, `waitForBlock`, `watchDoubleSpends` with `subscribeToDsproof`, the token balance wrappers (`getTokenUtxos`, `getTokenBalance`, `getNftTokenBalance`, `getAllTokenBalances`, `getAllNftTokenBalances`; Cashonize has its own), `HDWallet.fromSeed`, `fromXPub`, `fromXPriv`, `scanMoreAddresses`, `HDWalletEvents`, `getChangeTokenAddress`, `Wallet.fromPrivateKey`, `WifWallet` and its network classes, `parentDerivationPath`, `parentXPubKey`, `faucetServer`, `watchOnly`, `fromCashaddr`, `fromTokenaddr`, `fromPublicKey`, `publicKey`, `getPublicKey`, `getPublicKeyHash`, `getPublicKeyCompressed`, the `RegTest` and `WatchWallet` classes, `DEFAULT_BRANCHES`, `HDWalletOptions`, the static `networkPrefix` and `walletType`, and `HDWallet.getUtxos` / `getBalance`'s `branches`.
- A send can throw the new `BroadcastTimeoutError` (`txid`) when the server accepted the broadcast but neither reported the transaction within 30 seconds nor holds it when asked: the transaction may still reach the network. ## 6. Removed, re-add when needed

Round 3 cut these with no Cashonize use. Each may come back when a consumer needs it; the removal commit holds the old source.

- **Encrypted storage** (`EncryptedStorageProvider`, the `bch-wallet-lib/encrypted-storage` entry; `1b87512`, source at `git show 1b87512^:src/db/EncryptedStorageProvider.ts`). Cashonize wants wallet encryption over time. Redesign it rather than revert it:
  - it encrypted only the wallet-id rows, while an HD wallet's `walletCache-…` record holds its derived private keys as well;
  - encrypted rows break the storage freeze, as mainnet-js 3.1.7 cannot read them after a rollback, so adopting it needs an explicit opt-in and a migration story across both databases (`bitcoincash` and `bchtest`);
  - the `StorageProvider` interface has changed since (`getInfo`, `storeName` and `WalletDbEntryI.id` are gone);
  - 600k PBKDF2 iterations in pure JS need a performance check on mobile (Capacitor) before they gate opening a wallet.
- **The unsigned build path** (`buildUnsigned`, `UnsignedSendResponse`, `signUnsignedTransaction`; `333912e`). A watch-only or hardware-wallet feature would need it: build the transaction with its source outputs, sign elsewhere, broadcast. It signed every input with one P2PKH key, overwriting whatever unlock an input had, so it needs redoing (per-input keys, leaving inputs that are not the wallet's alone) rather than restoring.
- **`feePaidBy`** (`654810e`) **and the coin-control hooks** (`coinSelection`, `inputOrdering`, `outputOrdering`, `fee`, and the `bch-wallet-lib/coin-control` entry; `6240cfa`). Every review round found bugs in them (fees charged twice, unchecked shortfalls, hooks picking coins outside the pool). Re-add only one narrow option for a real need, e.g. an output that pays the fee for a sweep, not the general hooks.
- **The open migration gaps** are not removals but belong on the same list: a genesis input option on `tokenGenesis` (section 3 item 1), a token-coin narrowing for identity spends (item 5), and the review's open questions (item 6).
